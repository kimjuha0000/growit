# **다섯 번째 모험: 데이터에 생명을 불어넣는 마법의 노트, Zeppelin**

지금까지의 여정을 통해, 저는 마침내 반짝이는 보석(정제된 데이터)으로 가득 찬 진열장(PostgreSQL)을 갖게 되었습니다. 진열장 안의 데이터는 질서정연하게 정돈되어 있었지만, 여전히 숫자와 텍스트의 나열일 뿐이었죠. 이 데이터가 품고 있는 진짜 '이야기'를 듣고, 숨겨진 패턴을 발견하려면, 저는 데이터를 눈으로 볼 수 있어야 했습니다. 저에겐 데이터로 그림을 그릴 수 있는 '캔버스'가 필요했습니다.

그때 제 눈에 들어온 것이 바로 **아파치 제플린(Apache Zeppelin)**이었습니다.

## **왜 나의 캔버스로 'Zeppelin'을 선택했나?**

처음에는 코딩에 익숙한 제게 Jupyter 노트북이 더 맞지 않을까, 혹은 클릭만으로 멋진 차트를 만드는 BI 툴이 더 편하지 않을까 고민했습니다. 하지만 제플린을 발견한 순간, 이 모든 고민이 해결되었습니다. 제플린은 제가 원했던 모든 것을 갖춘 '하이브리드 캔버스'였습니다.

-   **여러 물감을 동시에 (멀티 인터프리터)**: 제플린의 가장 놀라운 점은 하나의 노트 안에서 여러 '언어'를 구사할 수 있다는 것이었습니다. 바로 위 칸에서는 SQL(`%jdbc`)로 PostgreSQL 진열장의 데이터를 조회하고, 바로 아래 칸에서는 파이썬(`%spark.pyspark`)으로 Spark를 이용해 Delta Lake의 원본 데이터를 직접 분석할 수 있었죠. 마치 여러 종류의 물감을 하나의 팔레트에서 사용하는 화가처럼요.
-   **간편함과 공유의 미학**: Docker로 단 몇 분 만에 설치할 수 있을 정도로 가벼웠고, 제가 분석한 결과와 차트가 담긴 노트를 팀원에게 링크 하나만으로 간단히 공유할 수 있었습니다. 데이터로부터 얻은 인사이트를 전파하기에 이보다 더 좋을 순 없었죠.
-   **코드와 시각화의 완벽한 조화**: 코드를 실행하면 결과가 테이블로 나오고, 그 테이블 위 버튼 몇 개만 클릭하면 바로 막대그래프, 선 그래프, 파이 차트로 변신했습니다. 코딩의 유연함과 시각화의 즉각적인 피드백을 동시에 누릴 수 있었죠.

## **나의 첫 작품: '일별 이벤트 수' 그리기**

제플린이라는 캔버스를 펼치고, 저는 가장 먼저 '일별 이벤트 수'라는 그림을 그려보기로 했습니다. 데이터 파이프라인이 살아 숨 쉬고 있다는 것을 가장 극적으로 보여주는 그림이 될 테니까요.

1.  먼저, 제플린 컨테이너를 실행하고(`docker compose up -d zeppelin`), 브라우저에서 새 노트를 열었습니다. 새하얀 캔버스 앞에 선 기분이었죠.
2.  첫 번째 문단(Paragraph)에, PostgreSQL에 접속하겠다는 신호인 `%jdbc`를 적고, 아래와 같이 SQL을 작성했습니다.

    ```sql
    -- 이 노트는 이제부터 PostgreSQL과 대화합니다.
    %jdbc 
    
    -- 날짜별로 이벤트가 몇 개씩 있었는지 알려주세요.
    SELECT event_date, COUNT(*) AS events
    FROM mart.events
    WHERE event_date IS NOT NULL
    GROUP BY event_date
    ORDER BY event_date;
    ```
3.  코드를 실행하자, 눈앞에 날짜와 이벤트 수가 담긴 표가 나타났습니다. 그리고 마법 같은 순간이 찾아왔습니다. 표 위의 'Bar Chart' 아이콘을 클릭하자, 딱딱했던 숫자들이 역동적인 막대그래프로 변신했습니다!

![Zeppelin Chart Example](https://zeppelin.apache.org/docs/0.10.1/assets/images/chart_bar.png)
*(실제 차트와 유사한 예시 이미지)*

저는 한눈에 어떤 날 사용자가 많았고, 어떤 날 적었는지 파악할 수 있었습니다. 데이터가 비로소 제게 말을 걸어오는 듯한 느낌이었습니다.

더 깊은 분석이 필요할 땐, Spark 인터프리터를 사용해 Delta Lake에 저장된 데이터를 직접 탐색하기도 했습니다.

```python
# 이번엔 Spark와 대화해볼까요.
%spark.pyspark

# Delta Lake에 저장된 데이터를 불러옵니다.
df = spark.read.format("delta").load("/data/delta/events")

# 가장 많이 발생한 이벤트 유형 Top 10을 보여주세요.
df.groupBy("type").count().orderBy("count", ascending=False).show(10)
```

## **나의 스케치북에서 얻은 몇 가지 팁**

-   **작품은 안전하게 보관하세요**: 제플린 컨테이너가 재시작되어도 제 소중한 분석 노트들이 사라지지 않도록, 노트와 설정 파일이 저장되는 폴더를 Docker 볼륨으로 연결해두는 것을 잊지 않았습니다.
-   **비밀번호는 그림에 남기지 마세요**: 노트 코드에 직접 데이터베이스 비밀번호를 적는 것은 위험한 일입니다. 저는 제플린의 인터프리터 설정 메뉴에 민감한 정보를 안전하게 등록해두고, 코드에서는 변수를 불러 쓰는 방식을 사용했습니다.

PostgreSQL이 데이터를 위한 '진열장'이었다면, 제플린은 그 진열된 보석들을 가지고 새로운 의미와 이야기를 창조하는 '예술가의 작업실'이었습니다. 이로써 저는 원본 데이터 수집부터 최종 분석과 시각화에 이르는 데이터 파이프라인의 전체 흐름을 완성할 수 있었습니다.
