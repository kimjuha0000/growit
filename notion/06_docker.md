# **마지막 장: 모든 것을 하나로, Docker Compose라는 마법 상자**

지금까지의 긴 여정을 통해 저는 웹 서버(FastAPI), 오브젝트 스토리지(MinIO), 데이터베이스(PostgreSQL), ETL 엔진(Spark), 그리고 시각화 도구(Zeppelin)까지, 데이터 파이프라인을 구성하는 모든 부품들을 하나씩 만들어냈습니다. 하지만 제 책상 위에는 잘 만들어진 부품들이 어지럽게 흩어져 있는 것과 같았습니다. 각 부품을 실행하고 서로 연결하는 방법은 저만 알고 있었죠.

만약 새로운 팀원이 합류한다면, 이 모든 시스템을 그의 컴퓨터에 똑같이 구축하는 데 며칠이 걸릴지도 모릅니다. 이것이 바로 개발자들이 흔히 겪는 "제 컴퓨터에서는 잘 되는데요!"라는 악몽의 시작입니다. 저에게는 이 모든 부품을 하나의 상자에 담아, 누구든 버튼 하나만 누르면 똑같이 작동하는 '마법 상자'를 만들 방법이 필요했습니다.

그 마법의 정체는 바로 **Docker**였습니다.

## **'Docker'라는 만능 규격 상자**

Docker는 제 각기 다른 서비스들을 각각의 '컨테이너'라는 규격화된 상자에 담을 수 있게 해주었습니다. 이 상자 안에는 애플리케이션과 그 실행에 필요한 모든 것(라이브러리, 설정 등)이 포함되어 있습니다. FastAPI 컨테이너, PostgreSQL 컨테이너, Spark 컨테이너... 이렇게 만들어진 컨테이너들은 제 노트북이든, 동료의 PC든, 아마존의 클라우드 서버든, 어디서나 똑같은 모습으로 완벽하게 작동합니다.

## **'Docker Compose'라는 조립 설명서**

하지만 이 수많은 상자들을 어떻게 관리하고, 서로 연결해줄 수 있을까요? 여기서 바로 마법 상자의 핵심인, **Docker Compose**가 등장합니다. `docker-compose.yml`이라는 파일은 이 모든 컨테이너들을 조립하는 '마스터 설계도'이자 '조립 설명서'입니다.

이 설계도에는 어떤 부품(서비스)들이 있는지, 각 부품은 어떤 포트를 사용하고 어떤 데이터를 보관하는지, 그리고 부품끼리 어떻게 서로 대화하는지가 모두 정의되어 있습니다.

### **마법 상자 설계도 엿보기 (`docker-compose.yml`)**

제 `docker-compose.yml` 파일의 일부를 단순화해서 보여드리면 이렇습니다.

```yaml
# docker-compose.yml (단순화된 버전)
version: '3.8'

services:
  # 1. 웹사이트와 API를 담당하는 'web' 서비스
  web:
    build: . # 현재 폴더의 Dockerfile로 이미지를 만듭니다.
    ports:
      - "3300:80" # 내 컴퓨터의 3300번 포트를 컨테이너의 80번 포트와 연결합니다.
    volumes:
      - ./data/bronze:/data/bronze/app # 로그가 저장될 폴더를 연결합니다.
    networks:
      - data-network # 다른 서비스와 소통할 네트워크에 참여합니다.

  # 2. 데이터를 저장할 Postgres 데이터베이스, 'pg' 서비스
  pg:
    image: postgres:15
    environment:
      POSTGRES_USER: ${POSTGRES_USER:-postgres}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:-password}
    ports:
      - "5432:5432"
    networks:
      - data-network

  # 3. 데이터 처리를 위한 Spark, 'spark' 서비스
  spark:
    image: bitnami/spark:3
    volumes:
      - ./spark/jobs:/opt/bitnami/spark/jobs
      - ./data:/data
    networks:
      - data-network
      
  # ... (minio, zeppelin 등 다른 서비스들도 유사하게 정의) ...

# 서비스들이 서로 소통할 수 있는 내부 네트워크
networks:
  data-network:
```

-   `services`: 상자 안에 들어갈 부품들입니다 (`web`, `pg`, `spark` ...).
-   `ports`: 컨테이너의 특정 포트를 제 컴퓨터의 포트와 연결하는 '창문'입니다.
-   `volumes`: 컨테이너가 사라져도 데이터는 보존될 수 있도록, 제 컴퓨터의 폴더와 컨테이너의 폴더를 연결하는 '외부 저장 공간'입니다.
-   `networks`: 컨테이너들이 서로 `pg`, `web` 같은 서비스 이름으로 대화할 수 있게 해주는 '내부 통신망'입니다.

## **마법 상자, 이제 조립해볼까요?**

이 설계도만 있으면, 이제 복잡한 설치 과정은 필요 없습니다. 몇 개의 간단한 명령어로 모든 것을 해결할 수 있습니다.

-   **조립 준비 (`.env` 파일 설정)**
    데이터베이스 비밀번호 등, 몇 가지 설정을 먼저 준비합니다.

-   **상자 제작 (`docker compose build`)**
    설계도를 바탕으로 각 서비스의 컨테이너 상자를 만드는 과정입니다.

-   **마법의 주문 (`docker compose up -d`)**
    제가 가장 좋아하는 명령어입니다. 이 한 줄의 주문으로, 설계도에 정의된 모든 서비스들이 백그라운드에서 일제히 생명을 얻고 작동하기 시작합니다!

-   **상자 속 확인하기 (`docker compose ps`, `docker compose logs`)**
    모든 부품이 잘 돌아가는지 확인하고 싶을 땐 `ps` 명령어로 상태를 보고, `logs` 명령어로 각 부품이 남기는 메시지를 엿볼 수 있습니다.

-   **정리하기 (`docker compose down`)**
    작업이 끝나면, 이 명령어로 모든 것을 깔끔하게 종료하고 정리할 수 있습니다.

## **여정의 끝, 그리고 새로운 시작**

Docker Compose 덕분에, 저의 복잡했던 데이터 파이프라인은 이제 하나의 프로젝트 폴더와 `docker-compose.yml` 파일로 완벽하게 재현 가능해졌습니다. 간단한 웹 페이지에서 시작했던 저의 작은 프로젝트는, 이제 누구든 단 하나의 명령어로 전체 시스템을 실행할 수 있는 견고한 '컨테이너화된 데이터 플랫폼'으로 거듭났습니다.

데이터 수집에서부터 저장, 처리, 분석, 시각화에 이르는 기나긴 여정의 마지막 퍼즐이 맞춰진 순간이었습니다. 이제 이 마법 상자는 어디로든 배송될 준비가 되었습니다.
