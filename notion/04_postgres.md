# **네 번째 발걸음: 보석을 진열하다, PostgreSQL 데이터 마트**

Spark라는 강력한 공방에서 원석(raw log)을 반짝이는 보석(clean data)으로 세공하는 데 성공했습니다. 하지만 이 보석들은 아직 공방의 작업대(Delta Lake) 위에 흩어져 있을 뿐이었죠. 기획자, 분석가, 심지어는 웹 애플리케이션조차 이 보석들의 가치를 제대로 보려면, 잘 정돈된 '진열장'이 필요했습니다. 누구나 쉽게 찾아와 구경하고, 질문하고, 필요한 보석을 가져갈 수 있는 그런 공간 말입니다.

저에게 그 진열장의 역할을 해준 것이 바로 **PostgreSQL**, 관계형 데이터베이스의 오랜 강자였습니다.

## **왜 진열장으로 'PostgreSQL'을 선택했나?**

세상에는 수많은 종류의 데이터베이스가 있지만, 제가 PostgreSQL을 선택한 이유는 명확했습니다.

-   **다재다능함 (SQL + JSONB)**: PostgreSQL은 정형 데이터(예: 사용자 ID, 이벤트 시간)는 물론, `JSONB`라는 강력한 기능을 통해 비정형 데이터(예: 이벤트의 세부 속성)까지 유연하게 다룰 수 있었습니다. 마치 완벽하게 커팅된 다이아몬드와 자유로운 형태의 조각품을 한 진열장에 함께 놓을 수 있는 것과 같았죠.
-   **신뢰성과 풍부한 생태계**: PostgreSQL은 수십 년간 검증된 안정성과 신뢰도를 자랑합니다. 또한, 문제가 생겼을 때 참고할 수 있는 방대한 문서와 커뮤니티가 있고, 거의 모든 분석 도구나 BI 툴과 손쉽게 연결된다는 점도 큰 매력이었습니다.
-   **규모의 적절성**: 현재 제 프로젝트의 규모에서, '분석을 위한 최종 데이터 저장소(Data Mart)'의 역할로는 PostgreSQL의 성능만으로도 충분하고도 남았습니다. 거대한 백화점보다는, 내실 있고 품격 있는 부티크가 제게는 더 필요했습니다.

## **진열장 설계하기: 데이터 마트의 구성**

저는 PostgreSQL 안에 `mart`라는 스키마(매장의 '코너' 개념)를 만들고, 두 종류의 테이블(진열대)을 배치했습니다.

-   `mart.events`: 모든 개별 이벤트를 하나하나 상세하게 볼 수 있는 메인 진열대입니다. "어떤 사용자가, 언제, 어디서, 무엇을 했는지"의 모든 기록이 담겨있죠.
-   `mart.daily_events`: 매일의 핵심 요약 정보를 보여주는 특별 진열대입니다. "날짜별 방문자 수", "가장 많이 본 콘텐츠" 등 미리 집계된 데이터를 담아, 더 빠른 요약 리포팅을 가능하게 합니다.

## **진열대에 보석 채우기: Spark에서 데이터 적재**

이전 Spark 이야기에서 보셨듯이, 데이터 세공 과정의 마지막 단계는 바로 이 PostgreSQL 진열장에 깨끗해진 보석들을 채워 넣는 것이었습니다.

```python
# Spark에서 PostgreSQL로 데이터를 쓰는 코드 (다시 한번 등장!)
(df_clean.write
 .format("jdbc") # JDBC, 데이터베이스와 대화하는 표준 방식
 .option("url", "jdbc:postgresql://pg:5432/postgres") # 진열장의 주소
 .option("dbtable", "mart.events") # 데이터를 넣을 진열대 이름
 .option("user", "postgres")
 .option("password", "password")
 .mode("overwrite") # 매일 새로운 데이터로 진열대를 완전히 교체
 .save())
```
여기서 `.mode("overwrite")` 옵션은 중요한 결정이었습니다. 매일 ETL 작업이 돌 때마다, 어제의 데이터는 모두 지우고 오늘의 신선한 데이터로 진열대를 완전히 새로 채우는 방식이죠. 덕분에 데이터 정합성을 항상 최신으로 유지할 수 있었습니다.

## **진열된 보석 감상하기: SQL로 질문 던지기**

진열장이 완성되니, 이제 누구나 SQL이라는 간단한 언어로 데이터에게 질문을 던질 수 있게 되었습니다.

마치 진열장 매니저에게 물건에 대해 묻는 것과 같았죠.

**"매니저님, 가장 최근에 들어온 신상품은 뭔가요?"**
```sql
-- 최신 이벤트 도착 시각 확인
SELECT 
  COUNT(*) AS total_rows, 
  MAX(props ->> 'timestamp') AS latest_event_time
FROM mart.events;
```

**"어제 하루 동안, 사용자별로 몇 개의 이벤트를 남겼는지 알려주세요."**
```sql
-- 사용자별 일일 이벤트 수 집계
SELECT 
  props ->> 'username' as user_name, 
  COUNT(*) as event_count
FROM mart.events
WHERE event_date = '2025-12-13' -- 어제 날짜
GROUP BY user_name
ORDER BY event_count DESC;
```

## **진열장을 항상 반짝이게: 운영 노하우**

진열장은 한 번 만들어두면 끝이 아니었습니다. 항상 깨끗하고 정돈된 상태를 유지해야 했죠.
-   **주기적인 청소와 정리 (`VACUUM ANALYZE`)**: PostgreSQL이 내부적으로 공간을 더 효율적으로 사용하고, 쿼리 성능을 최적화할 수 있도록 주기적으로 `VACUUM ANALYZE` 명령어를 실행해주는 것이 좋다는 것을 배웠습니다.
-   **"진열장은 복제품일 뿐"이라는 마음가짐**: 가장 중요한 깨달음이었습니다. PostgreSQL에 문제가 생겨 데이터가 모두 날아가더라도, 제게는 MinIO와 Delta Lake라는 안전한 금고에 '원본'이 있다는 사실이었죠. 덕분에 저는 PostgreSQL을 '조회용 복제품'이라 생각하며, 훨씬 가벼운 마음으로 운영할 수 있었습니다.

이제 데이터는 수집, 저장, 가공의 단계를 거쳐 마침내 '분석'이라는 최종 목적지에 도달했습니다. PostgreSQL이라는 반짝이는 진열장 덕분에, 데이터는 더 이상 개발자의 전유물이 아닌, 모두의 자산이 되었습니다.
